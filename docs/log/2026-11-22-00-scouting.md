## آنچه روی دستگاه دیدیم

```
Linux ubuntu 6.6.144-android15-8-abA145PXXUEDZJ2-4k-behi-v1.6.1 aarch64
Ubuntu 26.04.1 LTS (resolute), uid=0, HOME=/root
OLDPWD=/root/android_device_samsung_a14m
ro.board.platform=mt6768
ro.product.board=a14m
/proc/device-tree/model = MT6769V/CT
```

- 8 CPU: 2× Cortex-A75 @2GHz + 6× Cortex-A55 @1.8GHz.
- 3.6 GiB RAM، 2 GiB swap، `/data` 50G f2fs با 36G آزاد،MicroSD exFAT.
- `/system/build.prop` متعلق به GSI اندروید ۱۷ است
  (`google/infinity_gsi/tdgsi_arm64_ab`) → مب UT نباید روی GSI فعلی بسازیم.
- Overlayهای KernelSU: `behi_uka`, `ubuntu-chroot`, `a145p_sms_pending_fix`.
- `/cache` ext4 rw، `/metadata` ext4 ro، `/persist` ext4 rw.

## از درخت TWRP

- ریپازیتوری `Behrooz140/android_device_samsung_a14m`، branch `main`،
  HEAD `eb19a1d`، تگهای `build-23` … `build-32`، لایسنس Apache-2.0.

## تصمیم ۶: تست اولیه از طریق DSU

روی دستگاه `/system/bin/gsi_tool` و `/system/bin/gsid` موجوداند و پارتیشنهای
dynamic هم داریم → DSU قابل استفاده است. طبق متن کمک `gsi_tool`، نصب تنها
`system` + `userdata` را انجام میدهد و بوت ایمیج سفارشی ندارد؛ بنابراین DSU
بهتنهایی UT را بوت نمیکند، ولی برای تست ایمن لایهٔ Halium عالی است. جزئیات کامل
در [docs/dsu.md](../dsu.md).
